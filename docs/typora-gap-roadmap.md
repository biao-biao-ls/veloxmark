## 1. 现状审计：已实现能力

### 1.1 编辑器内核（完成度最高）

| 能力 | 实现 | 备注 |
|---|---|---|
| Typora 式 live preview | `editor/livePreview.ts` StateField 装饰引擎：光标行源码态，离开即渲染 | 核心卖点已成立 |
| 内联样式 | 粗体/斜体/删除线/行内代码/链接：标记隐藏 + mark 装饰 | |
| 块级结构 | 标题（H1–H6 行装饰）、列表（深度分级）、引用（深度分级）、分隔线 | |
| 代码块 | `CodeBlockWidget` + highlight.js，语言标签，点击回源码 | |
| 数学公式 | 块级 `$$` + 行内 `$…$`，KaTeX；正则扫描实现（非语法树扩展） | |
| Mermaid | `MermaidWidget` + 渲染缓存 + 明暗主题 + **SVG 导出按钮** | 超出 README 描述 |
| GFM 表格 | `TableWidget` + `tableParse.ts`（对齐、单元格内联 md，有单测） | **README 仍写"按源码显示"，已过时** |
| 任务列表 | `TaskWidget` 可点击复选框，写回源码 | |
| 图片 | 相对/绝对/网络路径；`mdres://` 协议（`electron/main.ts`）；JS Map 缓存 | 仅"显示"，无工作流 |
| 快捷键 | `Mod-B/I/E` 包裹；CM search 面板（含替换）；撤销/重做；Tab 缩进 | |
| 其他 | 多选区、行软换行、行号、GFM 扩展 | |

### 1.2 文档与文件操作

- 新建 / 打开 / 保存 / 另存为（`hooks/useDocument.ts`）
- **原子写**：临时文件 + rename（`electron/main.ts` `fileWrite`）
- **外部修改冲突检测**：mtime+size stamp，保存前比对，冲突可确认覆盖
- **脏关闭守卫**：关闭拦截 → Save / Don't Save / Cancel；Save As 取消可中止关闭
- macOS Finder "打开方式"/双击接入：`open-file` 事件 + 渲染器就绪前排队；文件关联已配置（`electron-builder.yml`：md/markdown/mdown）
- 未保存标记：标题栏 `•` + 窗口标题同步（`app:setState`）

### 1.3 文件夹工作区

- 打开文件夹 → 递归 Markdown 树（跳过 `node_modules`/`.git` 等，深度上限 8，仅保留含 md 的目录）
- `fs.watch` 递归监听 + 200ms 防抖全量刷新
- 树 CRUD：新建文件 / 重命名 / 删除（右键菜单 `TreeMenu`）
- 路径跟随：打开文件被改名/移动时编辑器自动改绑路径（`reattachIfUnder`）；被删除时转为待另存缓冲（`detachIfUnder`）

### 1.4 外壳与平台集成

- macOS：`titleBarStyle: hiddenInset` + 原生红绿灯 + **原生菜单栏**（`buildDarwinMenu`：`⌘Q/H/W/M`、Edit roles、Services）
- Windows/Linux：自绘无边框标题栏 + 应用内主题菜单（`MenuBar`）
- 侧栏双模式：大纲（当前位置高亮、点击跳转 `Outline`）↔ 文件树（可返回）
- 明暗主题：localStorage 持久化，联动 CM6 主题 / hljs 主题 / mermaid 主题（`useTheme`）
- 窗口缩放、全屏同步（红绿灯空间预留）、devtools、内置 Markdown 语法帮助（`content/docs.ts`）

### 1.5 安全与工程质量

- `contextIsolation` + `sandbox` + preload 桥；`will-navigate` 全拦截；`setWindowOpenHandler` 白名单（http/https/mailto → `shell.openExternal`）
- vitest 单测：`shared/paths`、`outline/extract`、`editor/tableParse`
- 分层清晰：`hooks/`（useDocument / useWorkspace / useTheme）、`components/`、`editor/`；IPC 契约集中于 `shared/ipc.ts`

## 3. 与 Typora 的逐项差距分析

### 🔴 P0 — 核心写作闭环（用户每天都会撞到）

1. **图片工作流基本缺失**
   - 不能拖拽图片文件进编辑器（无 drop handler）
   - 不能粘贴剪贴板图片（`editPaste` 只读文本；Typora 粘贴截图自动落盘 `assets/` 并插入引用）
   - 不能拖拽调整图片尺寸（Typora 拖角写入 `width` 属性）
   - 点击图片无放大预览
   - → 拆为 **R-02 / R-03**
2. **表格只能整块编辑**：点击表格 → 跳到源码开头整块回源码态；Typora 是单元格内直接编辑、Tab 跳格、行列工具、拖列宽
   - → 拆为 **R-09 / R-10**（R-09 可先做过渡形态）
3. **无源码模式切换**：只能靠移动光标逐块"揭开"；无 `⌘/` 一键全局切换
   - → **R-01**（小工作量、高杠杆）
4. **单文档缓冲区**：打开新文件必须丢弃当前文档；无标签页
   - → **R-05**（架构性改动，需独立设计）
5. **链接不可点击跳转**：外链无 `openExternal` 通路；相对 md 链接无法内部跳转
   - → **R-04**

### 🟠 P1 — 输出交付

| 能力 | Typora | VeloxMark | 需求 |
|---|---|---|---|
| 导出 PDF（书签/主题） | ✅ | ❌ | **R-06** |
| 打印 | ✅（print CSS） | ❌ | **R-06**（同一条，共享渲染路径） |
| 导出 HTML | ✅ | ❌ | **R-07** |
| 复制为 Markdown/富文本 | ✅ | ❌ | **R-08** |
| Word/EPUB/LaTeX（Pandoc） | ✅ | ❌ | 暂不立项（见 §6 说明） |

### 🟡 P2 — 写作增强（"用了回不去"项）

- 专注/打字机模式（当前 `highlightActiveLine: transparent`，无居中滚动/dim）→ **R-13**
- 偏好设置面板（零设置项；字号固定 16px，缩放是整窗 zoom 连 UI 一起放大）→ **R-11**
- 自动保存 / 会话恢复（重启不恢复上次文件/文件夹）→ **R-12**
- YAML front matter 特殊解析 → **R-15**
- `[TOC]` 目录生成 → **R-17**
- 列表编辑辅助（自动续号、Tab/Shift+Tab 调层级——当前 indentWithTab 只插空格、无自动配对 `**`/`` ` ``）→ **R-16**
- 字数统计 / 状态栏 → **R-14**
- 文件树增强（新建文件夹、拖拽移动、非 md 文件可见性、废纸篓删除）→ **R-18**
- 文件夹全局搜索 → **R-19**
- 自定义 CSS 主题生态 → **R-22**

### 🟢 P3 — 平台与产品完善

- 无「最近打开」菜单、无窗口状态记忆 → **R-21**
- 无自动更新（`electron-builder.yml` 已预留 zip target + publish 注释位）→ **R-23**
- 对话框全是 `window.confirm/alert/prompt`，深色主题下观感断裂 → **R-20**
- 大文档性能（全文档正则 × 3 遍 + 每次变更全量重建装饰）→ **R-24**
- 单窗口；无 i18n（界面英文，字体栈中文优先）→ 多窗口暂不立项；i18n → **R-25**

## 5. 需求清单（R-01 ~ R-25）

> 粒度约定：每条 R-xx = 一个可独立开分支/PR 的需求，含明确验收标准（AC）。
> 预估工作量：S ≤ 0.5 天；M ≈ 1–3 天；L > 3 天（单人全职粗估）。

### M1 — 写作闭环（P0）

#### R-01 源码模式切换 · S
- **范围**：全局"源码/预览"模式开关。源码模式下停用全部 live-preview 装饰（仅保留 CM 语法高亮）；预览模式恢复现行为。快捷键 `⌘/`（`Ctrl+/`）+ View 菜单项 + 状态记忆（localStorage）。
- **AC**
  - [ ] 切到源码模式：全文显示原始 Markdown 标记，代码/公式/图不再被 Widget 替换
  - [ ] 切回预览模式：装饰即时恢复，光标位置不跳动
  - [ ] 菜单（应用内菜单 + macOS 原生菜单）均可触发，快捷键一致
  - [ ] 重启后记住上次模式
- **依赖**：无 ｜ 关联技术债：T-1

#### R-02 图片工作流：拖入与粘贴落盘 · M
- **范围**
  1. 拖拽图片文件到编辑器 → 复制到当前文档同级 `assets/`（无未保存文档时提示先保存）→ 插入相对路径引用 `![](assets/xxx.png)`
  2. 粘贴剪贴板位图（截图）→ 同上落盘 + 插入
  3. 粘贴/拖入图片 URL → 直接插入网络引用
- **AC**
  - [ ] 从 Finder 拖入 png/jpg/gif/webp：文件出现在 `assets/`，编辑器插入相对引用且立即渲染
  - [ ] 截图后 `⌘V`：落盘 + 插入
  - [ ] 未保存（Untitled）缓冲执行上述操作：明确提示，不静默丢图
  - [ ] 文件名冲突自动去重（`name-1.png`）
  - [ ] 落盘文件不触发文件夹监听的误刷新死循环（watcher 已忽略点开头临时文件，需验证 assets 场景）
- **依赖**：无 ｜ 关联技术债：T-3、T-5

#### R-03 图片交互：缩放与预览 · S–M
- **范围**：图片 Widget 悬停显示拖拽手柄改宽（写入 `` <img width="…" > `` 语法或 HTML img 属性，与 Typora 兼容）；点击图片进入灯箱预览（Esc/点击空白关闭）。
- **AC**
  - [ ] 拖角/拖边改变显示宽度，源码中写入可往返的宽度信息
  - [ ] 带宽度的图片重新打开后保持尺寸
  - [ ] 点击灯箱预览，Esc 关闭；预览态不触发"回源码"跳转
- **依赖**：R-02（同一图片子系统，建议同分支系列）

#### R-04 链接点击跳转 · S
- **范围**：预览态链接可点击：`http(s)://`/`mailto:` → 系统浏览器（已有白名单通路）；相对/绝对 `.md` 路径 → 应用内打开目标文档（脏文档问询复用现有 `confirmDiscard`）；修饰键与 Typora 对齐（单击或 `⌘+单击`，实现时定一种并写进帮助文档）。
- **AC**
  - [ ] 预览态点击外链在系统浏览器打开，绝不窗口内导航
  - [ ] `./sibling.md`、`../doc.md`、绝对路径 md 均能在应用内打开
  - [ ] 指向不存在文件的链接给出提示而非崩溃
  - [ ] 链接在源码态（光标所在行）保持可选中文本，不劫持点击
- **依赖**：无

#### R-05 多文档标签页 · L
- **范围**：标签栏（每个打开的文件一个 tab，脏标记 `•`，中键/×关闭）；切换 tab 不丢各缓冲状态（含撤销历史、滚动位置）；关闭脏 tab 触发问询；文件树点击行为改为"聚焦已有 tab 或新 tab"。
- **AC**
  - [ ] 打开 ≥2 文件可来回切换，各自修改互不覆盖
  - [ ] tab 内关闭脏文档弹出保存问询
  - [ ] 窗口关闭守卫升级为遍历所有脏 tab
  - [ ] 外部修改冲突检测按 tab 各自持有 stamp（现 `openFileStamp` 是主进程单例——需重构为按路径/会话）
- **依赖**：无前置，但建议在 R-11/R-12 之前做架构评审；是 M1 中唯一的架构性需求，可独立后置到 M1.5

### M2 — 输出交付（P1）

#### R-06 导出 PDF 与打印 · M
- **范围**：`File → Export → PDF…`（另存对话框）+ `File → Print…`；独立打印 CSS（A4/Letter 边距、代码块不断行、链接显示 URL 等）；PDF 带标题书签（利用现有大纲提取）。
- **AC**
  - [ ] 导出的 PDF 视觉与应用内预览一致（代码高亮/KaTeX/mermaid/表格均正确）
  - [ ] 打印对话框可用（`webContents.print`）
  - [ ] 明暗主题分别有合理打印样式（打印默认白底）
  - [ ] 菜单：应用内 + macOS 原生双侧入口
- **依赖**：无；建议先做打印 CSS 再接 `printToPDF`

#### R-07 导出 HTML · S
- **范围**：导出单文件 HTML（内联基础 CSS，图片可选内联 base64 或相对引用）。
- **AC**
  - [ ] 导出文件在浏览器打开样式正确、离线可用（图片内联时）
  - [ ] 相对引用模式下图片路径相对导出位置正确
- **依赖**：可复用 R-06 的渲染样式抽取

#### R-08 复制为 Markdown / 富文本 · S
- **范围**：`Edit → Copy As → Markdown / Rich Text`（富文本经选区 HTML 渲染）。
- **AC**
  - [ ] 选中内容复制为富文本粘贴到微信/邮件保留样式
  - [ ] Copy As Markdown 等价于源码复制
- **依赖**：无

> Pandoc 系导出（Word/EPUB/LaTeX）**暂不立项**：需捆绑 Pandoc 二进制（~30MB/平台），对"阅读器优先"定位收益低；若未来立项单独立为 R-xx。

### M3 — 表格编辑体验（P1）

#### R-09 表格单元格级编辑（过渡形态）· M
- **范围**：渲染态表格点击单元格 → 光标定位到该单元格源码位置（行列映射，复用 `tableParse`）；单元格内源码态编辑时其余行仍保持渲染；Esc/点击表外回到全渲染。
- **AC**
  - [ ] 点击任意单元格，光标精确落到源码对应单元格内
  - [ ] 编辑某个单元格时表格其余部分保持渲染（非整块掀开）
  - [ ] `tableParse` 补齐单元格内图片/转义竖线的测试（T-3）
- **依赖**：无；是 R-10 的前置探路

#### R-10 表格结构操作 · M–L
- **范围**：Tab/Shift+Tab 单元格间移动与行尾自动加行；右键或悬浮工具条：增删行列；拖拽列宽（写入源码对齐填充或放弃对齐格式，实现时决策并记录）。
- **AC**
  - [ ] Tab 在单元格间移动，最后一格 Tab 新建行
  - [ ] 插入/删除行列后 Markdown 表结构合法（分隔行同步）
  - [ ] 操作后可无损往返（存盘仍是纯 md）
- **依赖**：R-09

### M4 — 偏好与写作增强（P2）

#### R-11 偏好设置面板 · M
- **范围**：设置入口（菜单 + 快捷键 `⌘,`）；首版项：编辑器字号/字体、行距、内容最大宽度（居中排版）、是否显示行号、自动保存开关（联动 R-12）。持久化 localStorage，后续可迁 JSON 配置文件。
- **AC**
  - [ ] 字号/行距/宽度即时生效且重启保持
  - [ ] 仅编辑器内容缩放，UI chrome 不受影响（区别于现有整窗 zoom）
  - [ ] 设置面板自身跟随明暗主题

## 6. 里程碑与实施顺序

```
M0 基线加固（穿插，~0.5 周）
   T-1 README 更新 · R-24 基线压测先行部分 · R-20 原生对话框
   理由：图片/表格会新增大量提示框与装饰负载，先把地基打好

M1 写作闭环（P0，~2 周）
   R-01 源码模式 → R-02 图片拖入/粘贴 → R-03 图片缩放/预览 → R-04 链接跳转
   R-05 多标签页（可后置为 M1.5，先做架构评审）

M2 输出交付（P1，~1 周）
   R-06 PDF/打印 → R-07 HTML → R-08 Copy As

M3 表格编辑（P1，~1.5 周）
   R-09 单元格定位编辑 → R-10 行列操作

M4 偏好与增强（P2，~2–3 周，可与 M2/M3 并行穿插）
   R-11 设置面板 →（R-12 自动保存/会话 · R-13 专注模式 · R-16 列表增强）
   R-14 状态栏 · R-15 front matter · R-17 TOC · R-18 文件树 · R-19 全局搜索

M5 产品完善（P3，持续）
   R-21 最近打开/窗口状态 → R-22 自定义主题 → R-24 性能收尾 → R-25 i18n → R-23 自动更新（依赖发版线签名）
```

排序原则：
1. **先闭环后深度**：图片/链接/源码模式决定"能不能认真用"，表格编辑决定"好不好用"。
2. **先地基后楼层**：R-20/R-24 前置，避免后续每条需求反复偿还。
3. **架构性需求单独评审**：R-05（多标签）、R-24（增量装饰）不与功能需求混在一个 PR。
4. **发版线独立**：R-23 自动更新以签名为前提，跟随 `docs/*-release-guide.md` 的阶段 B，不阻塞产品功能线。

## 7. 拆分与执行约定

后续从本文档拆需求时遵循：

1. **一条 R-xx = 一个分支 + 一个 PR**：分支名 `feat/R-02-image-paste` 式；PR 描述链接本文档对应小节。
2. **拆得更细时编号派生**：如 R-02 拆两步即 `R-02a`（拖入落盘）/ `R-02b`（粘贴位图），本文档同步改写该条。
3. **AC 即验收**：PR 合并前逐条勾选 AC；做不到的项要么砍出范围写明去向，要么回本文档改需求本身。
4. **完成标记**：在本文件该条标题后追加 `（✅ v0.x.y）`，并在 README 特性表同步。
5. **发现新差距**：先在 §3 追加分析，再分配 R-26+ 编号进 §5，不直接开做（保持路线图是唯一事实源）。
6. **技术债**：T-xx 可附着在相关 R-xx 内解决；独立解决时单独 PR 并引用 T 编号。

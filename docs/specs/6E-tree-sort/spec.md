# 6E 文件树排序体系（任务 6.9 + 6.10）

## What / Why

排序从写死（目录优先 + `localeCompare`，`electron/ipc/folder.ts:89-92`）扩为 Typora「操作」面板排序行语义（用户 2026-09-23 确认）：**按文件夹分组**（toggle）、**自然排序**（升序|降序）、**按文件名排序**（升序|降序）、**按修改时间排序**（升序|降序）、**按创建时间排序**（升序|降序）。评估 P1-4c/P1-5——排序不可选、大目录定位低效。

## 背景与现状

- 主进程 `listMarkdownTree` 深度优先构建树时固定「目录在前文件在后，各自 `localeCompare` 文件名」（`folder.ts:89-92`）；渲染端按到达序展示。
- `DirNode` 形状 = `name/path/isDir/children?`（`electron/shared/api.ts:8-13`），**无时间戳字段**——修改/创建时间排序无数据源。
- 排序状态无任何偏好字段；「操作」面板排序行 UI 归 6D 面板容器（本单元提供状态机与数据面）。
- 列表视图（6.12）将共用同一排序状态。

## 验收标准（AC）

1. 五项语义齐全，状态可视化（操作面板排序行：toggle 态 + 当前排序键 + 升/降方向）。
2. 排序作用于树视图**与**列表视图（6.12 落地后零改动接入）。
3. 修改/创建时间比较有数据：目录扫描携带 mtime/birthtime（`DirNode` 只增字段）。
4. 两比较器语义可区分且有单测：自然排序 = 数字感知（`2.md` < `10.md`）；文件名排序 = 字符串字典序。
5. 「按文件夹分组」= 目录聚组在前的开关（关 = 文件目录混排按当前键）。
6. 排序偏好持久化，重启保持。

## 约束

- 比较器/排序纯函数落渲染端（树数据已全量在渲染端），配 `*.test.ts`（Constitution 纯逻辑模块必测）；**不为排序回主进程重扫**。
- `DirNode` 只增字段（`mtimeMs`/`birthtimeMs`，可选缺省），不删改既有；IPC channel 名不改。
- i18n：排序行文案 en+zh 同加。
- 间距 token 纪律、深浅主题一致。

# P10 表格单元格级编辑

优先级：P10 | 类别：UX/功能 | 预估规模：L

## 背景

V1 刻意将表格读态做成整块 HTML Widget（`TableWidget`），点击跳回源码
（记忆中的已知决策，留 V2）。Typora 的表格体验：单元格内直接编辑、Tab
跳到下一格、行列增删按钮、对齐切换、拖拽列宽。这是差距分析中最大的功能
单项之一。

## 目标

表格渲染态支持单元格级编辑与行列操作，只有进入"单元格编辑"时才显示该
单元格的 Markdown 源码；操作结果直接写回表格源文本。

## 功能需求

### 单元格编辑
- [ ] 单击单元格进入编辑：该单元格内容从渲染态切换为源码态（行内标记
      按 live preview 规则处理），其余单元格保持渲染
- [ ] Tab / Shift+Tab 在单元格间移动（末格 Tab 自动在末尾追加新行）
- [ ] Enter 在单元格内换行（转义或 `<br>`——采用 Typora 语义：单元格内
      Enter 移到下方单元格，换行用 Shift+Enter → 写入 `<br>`）
- [ ] Esc 退出单元格编辑（整表回到纯渲染态）
- [ ] 方向键在单元格边界处跨格移动

### 行列操作
- [ ] 选中单元格时行首/列顶出现操作把手：+行 -行 +列 -列
- [ ] 右键菜单：插入/删除行列、切换对齐（左/中/右）、剪切/复制/粘贴单元格
- [ ] 拖拽列宽：调整结果写入源码不可行（Markdown 无列宽语义）——列宽仅
      会话内生效，或写入 HTML 注释扩展（首版做会话内）
- [ ] 表格整体对齐操作后自动重排 `|` 使源码整齐（format table）

## 技术方案要点

- 这是 CM6 上的高难改造，推荐路线：**保持 Markdown 文本为唯一数据源**，
  表格仍整体 replace 为 Widget，但 Widget 内部是真 DOM 表格 + contentEditable
  式单元格；单元格编辑时把该单元格源码写回文档（通过 transaction 定位
  到表格源文本中对应 cell 的字符范围）。
- 关键算法：**源码 cell ↔ DOM cell 映射**。解析表格源文本（复用
  `widgets.ts` 的 `splitRow`，但需保留每 cell 的源内偏移），操作时按偏移
  做 `view.dispatch`。
- 备选路线（不推荐）：放弃整块 Widget，改为逐行装饰 + 表格线 CSS——
  实现更标准但渲染质量（列宽对齐、内边距）难达 HTML table 水准。
- 操作把手与右键菜单组件可复用 P02 Dialog 体系的浮层模式（`TreeMenu.tsx`
  已有右键菜单先例）。
- 建议拆三个阶段交付：① Tab/方向键导航 + 单元格编辑；② 行列增删 +
  右键菜单；③ 格式化重排 + 列宽。

## 验收标准

1. 单击表格单元格即可输入，输入 `**b**` 离开该格后渲染为粗体。
2. Tab 依次走完一行自动续下一行；在最后一格 Tab 生成新行且源码 `|`
   对齐合法。
3. 删一行后源码行数 -1，表格无残影；undo 可完整回退（历史为文档级）。
4. 对齐切换后 delimiter 行 `:---:` 正确更新，渲染即时生效。
5. 表格内粘贴 TSV（Excel 复制）自动铺开为多单元格（高价值，尽量纳入）。

## 非目标

- 合并单元格（Markdown 不支持）、公式计算。

# P09 行内元素细粒度 WYSIWYG

优先级：P09 | 类别：UX | 预估规模：L

## 背景

当前 `livePreview.ts` 的 `touched()` 以**行为粒度**判断：光标进入某行，该行
所有隐藏标记全部显示。后果是光标从左往右经过 `**bold**` 时整行闪回源码，
与 Typora 的"标记逐字符出现/消失"差距明显。这是实时预览质感的核心差距，
也是技术上最难的一项（列后置，等 P01–P08 基建完成）。

## 目标

把"显示源码"的粒度从行细化到**标记（mark）级别**：只有光标紧邻/位于某个
标记内时该标记显示，其余始终隐藏渲染。

## 功能需求

- [ ] 行内标记（`**`、`*`、`~~`、`` ` ``、链接 `[]()`）：光标在标记**内部
      文本**中时，显示该标记的 delimiters；光标离开立即隐藏
- [ ] 判定规则细化为"光标位置在 [markFrom, markTo] 内即显示"，替代
      整行 `touched`；跨行选区（拖选）时选区触及的标记显示
- [ ] ATX 标题 `#`：光标在标题行内显示 `#`，离开隐藏（行级粒度可接受）
- [ ] 列表标记 `-`/`1.`：光标在标记字符上才显示（光标进入文本后隐藏）——
      Typora 行为；若实现风险大可保持行级，作为降级验收
- [ ] 边界行为：光标恰好在 `**|**`（空 strong）等退化情况不闪烁、不死循环
- [ ] 性能：装饰重建不因粒度细化而从 O(整文档) 恶化——行内判断本来就在
      树遍历内，预期无额外成本；需基准测试 5k 行文档

## 技术方案要点

- 核心改动集中在 `livePreview.ts` 的 `touched` / `blockTouched` 逻辑：
  - 行内标记类节点：改用 `selections.some(r => r.from >= node.from &&
    r.from <= node.to)`（光标在节点内）或选区与节点相交
  - 块级 Widget（代码/数学/表格/mermaid）维持现有 `blockTouched`（块粒度
    足够，Typora 也是块粒度）
- 风险点：
  - **光标在隐藏标记上的可达性**：标记被 `Decoration.replace` 隐藏后光标
    无法"停在"隐藏文本上，CM6 会把光标吸附到两端——需验证隐藏标记边缘的
    移动手感（Typora 用的是原子替换 + 特殊光标处理）。若吸附感太强，
    退路方案：标记改为"零视觉重量但保留宽度 0" + `atomicRanges` 控制。
  - 与 `markEm`/`markStrong` 等 mark 装饰的共存：显示标记时不移除样式类。
- 建议先做 spike：只改 `EmphasisMark` 一个节点类型，验证手感后再推广。

## 验收标准

1. `This is **bo|ld** text`：光标在 bold 内部时两侧 `**` 可见，光标移出
   立即隐藏——**没有整行其他标记闪变**。
2. 一行内多个标记（`*a* and **b**`）独立显隐互不影响。
3. 从行首按 → 逐字符移动：标记出现/消失平滑，无位置跳动。
4. 5k 行文档输入延迟无可感知劣化（对比 P09 前基准）。

## 非目标

- 行内代码/链接的"所见即所得目标编辑"（点链接直接改 URL）——可另立需求。
